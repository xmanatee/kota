The linked-worktree Git directory is outside the builder sandbox's writable
roots. The canonical task CLI therefore rolled back its first ready -> doing
attempt when Git could not create the real worktree index.lock. A second attempt
with a writable alternate index still rolled back because the shared object
database was also protected.

The successful task-state operations use the same source CLI and domain
mutation path with a run-specific index and object database under /private/tmp,
plus the canonical repository object database as a read-only alternate. This
preserves the CLI's exact-path staging and rollback semantics without writing
the protected linked-worktree metadata. Final `git add -A` is performed against
that alternate index; the workflow's trusted-host staging bridge must replay
the staged workspace changes into the real worktree index before commit.

The pinned pnpm 10.32.1 launcher also could not fetch registry signatures in
the network-restricted sandbox. Validation therefore invoked the already
installed local TypeScript, Biome, and Vitest binaries directly, with the same
source conditions and TMPDIR used by the package scripts.
