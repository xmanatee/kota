Runtime Probe mutable-workspace containment regression

Baseline

- Git-HEAD provenance authenticated only the task declaration.
- The critic then launched pnpm directly from the mutable workspace.
- Staged or untracked package scripts therefore executed as daemon-host code.

Final boundary

- Executable probes require Linux prlimit and Bubblewrap. Bubblewrap exposes only
  pinned read-only runtime paths and a disposable tmpfs overlay of the project
  inside empty mount, network, IPC, and PID namespaces. Package-created files
  and pathname IPC are invisible to the host. Git and external regular-file
  aliases are nested read-only mounts.
- Before launch, the resolver reads the live host `core_pattern`. A pipe pattern
  rejects execution because Linux ignores `RLIMIT_CORE=0` for pipe handlers and
  launches them in the host's initial namespaces. Accepted file-pattern hosts
  enter Bubblewrap through prlimit with both core limits locked at zero. The
  capability program then execs a fresh Node child and requires its deliberate
  abort to terminate with `SIGABRT`, covering the post-exec fatal-signal path
  before mutable package code may run.
- The live capability program launches a detached child. After the sandbox
  command exits, any survivor writes to an inherited pipe observed by trusted
  host code. The witness is outside the project tmpfs overlay, so namespace
  teardown evidence cannot pass merely because a marker was hidden. The
  enforced artifact records `processBoundary: "pid-namespace"`.
- macOS Seatbelt execution was removed. Its inherited filesystem/network policy
  does not stop package code from escaping launcher process-group cleanup with
  `setsid` or `spawn(..., { detached: true })`. macOS and every unsupported host
  now record `verdict=fail`, `execution=not-executed`, and
  `isolation.status=unavailable`; there is no host fallback.
- Before launch, every FIFO, pathname socket, device, or other active special
  inode rejects execution regardless of link count because namespace isolation
  cannot sever host pathname IPC. Inode link counts additionally find regular
  workspace files with outside names and freeze their root file or bounded
  top-level tree. Ordinary symlinks remain constrained by the empty root.
- The task-probe public surface exposes only `runTaskProbe`; callers cannot
  inject an arbitrary object that merely claims to provide a sandbox.

Regression result

- `critic-runtime-probe-sandbox.integration.test.ts` preserves trusted
  git-HEAD task provenance while supplying staged and untracked package code.
  Each hostile package attempts sibling reads/writes, an outside-inode regular
  hard-link write, host Unix-socket access, `osascript` delegation, and a
  detached child that writes after its launcher exits. Enforced runs must pass
  and emit package-originated launch and socket-creation evidence; unsupported
  hosts must record explicit failed non-execution. Neither package-created
  names may appear in the host workspace, and inherited output must contain the
  child-ready handshake but not the delayed survival witness.
- A separate integration creates a real ordinary single-link FIFO and proves
  package code never launches. Focused unit coverage verifies regular-file
  protection, ordinary FIFO rejection, and a Linux pathname-socket inode case.
- The fixed Node supervisor still kills the initial process group on timeout
  and launcher exit as defense in depth. It is not described or accepted as
  the descendant lifetime boundary.
