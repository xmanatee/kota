Scientific-claim analyzer resource-exhaustion regression

Production boundary
- Analyzer verification receives the executor's configured Docker-compatible backend explicitly.
- Host-subprocess runs return an unavailable boundary and never launch agent-produced JavaScript.
- Every analyzer case uses a fresh `run --rm --init` container with network none, a read-only root, a read-only exact case-directory mount, one writable output-file mount, no capabilities, no-new-privileges, and the host uid/gid.
- Hard resource controls are `--memory 256m`, `--memory-swap 256m`, `--cpus 0.5`, `--pids-limit 32`, `--ulimit cpu=10:10`, `--ulimit nofile=64:64`, and a 16 MiB noexec tmpfs.
- The 15-second host timeout and output buffer remain secondary controls. A timed-out or output-flooded container is force-removed by its validated CID.
- Trusted artifact validation rejects non-regular outputs and logical sizes above 256 KiB before `readFileSync`, so a successful analyzer cannot turn its writable result-file mount into unbounded host allocation.

Regression evidence
- The Docker-compatible test runtime captured and asserted every production resource, filesystem, privilege, and network argument.
- The allocation-pressure analyzer retained unbounded arrays after an initial delay; while its execution promise was still pending, a 25 ms evaluator heartbeat won a `Promise.race`. The bounded test runtime then terminated the analyzer in under the five-second outer budget with a non-zero status.
- A successful analyzer created an 8 GiB sparse result through the real predicate execution path. The evaluator rejected the file at the 256 KiB metadata check without loading it into host memory.
- Analyzer launch, output capture, timeout termination, exact-CID cleanup, scientific predicate evaluation, and calibration propagation are asynchronous. Verification cases stay sequential to avoid multiplying the resource ceiling.
- Existing scientific-claim live-fixture and accepted-alternative calibration tests passed through the explicit predicate boundary.
