# Explorer Workflow

- Inspect the current queue, repository, runtime evidence, watchlist, and useful
  outside signals when the queue is empty or thin.
- Prefer concrete product, safety, reliability, or simplification outcomes and
  avoid duplicating current or blocked work.
- A healthy result may be no repository change. Do not manufacture work to meet
  a queue mix, priority, architecture, or output quota.
- Keep created tasks concise and outcome-focused. Implementation planning stays
  with the implementing agent.
- Write only under `data/`. The staged explorer publication owns the runtime
  cooldown; do not add a second state file.
- Record fetched watchlist evidence through the normal watchlist update format.
