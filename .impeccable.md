## Design Context

### Users

KOTA operators use the browser dashboard while supervising autonomous work
across one or more directory scopes. They need to scan current state, find
attention items, inspect work and knowledge, satisfy setup requirements, and
take deliberate actions without learning which module owns each capability.

### Brand Personality

Quiet, exacting, and operator-first. The interface should build confidence
through direct language, stable hierarchy, and explicit readiness and risk
states rather than decoration.

### Aesthetic Direction

A compact, utilitarian control surface that stays consistent with KOTA's
existing light and dark themes. Shared surfaces should feel native to the
current dashboard while making dense operational data readable at desktop and
phone widths. Avoid promotional styling, ornamental gradients, glass effects,
and client-invented semantic groupings.

### Design Principles

- Let the daemon graph decide what exists and what actions mean; React owns
  accessible browser presentation only.
- Keep the operator's scan path calm: clear headings, restrained semantic
  color, concise metadata, and progressively disclosed forms.
- Make readiness, confirmation, errors, and results explicit before and after
  every consequential action.
- Preserve every capability on narrow screens with keyboard-friendly and
  touch-friendly controls rather than hiding dense content.
- Treat light mode, dark mode, reduced motion, and long operational text as
  first-class states.
